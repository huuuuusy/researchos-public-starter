# 跨域科研入域工作流

## Agent Summary

本工作流帮助研究者与 AI 进入一个陌生或半陌生的科学领域，同时避免把流畅搜索误当成有效发现。它只冻结一个局部案例，建立够用的最小领域地图，让不同认识论角色独立搜索，保留候选谱系，用独立证据做准入，并分别检验人和新 AI 实例在撤除原脚手架后留下了什么，最后结算案例，而不是自动把结果晋升为长期记忆或公开主张。

这是一个可复用的能力内核。报告中的原型可以在运行时加入所有者的研究历史、判断偏好和私有材料，但这些输入仍归原型的所有者所有，不能复制到本插件。插件只包含步骤、模板和权威边界；它最终有多大威力，取决于使用者的判断、来源质量、模型能力、专家反馈和执行纪律。

## 这个插件做什么

插件服务于一个有边界的“科研入域案例”，不承诺学完整个学科，也不采用“持续提示直到著名问题看起来被解出”为默认策略。它复用 ResearchOS 已有的三种结果模式：

- `answer`：给出有边界的分析或下一步判断，不保存；
- `artifact`：生成可检查的 Case Pack；
- `writeback`：把候选 Case Pack 送入 Review；插件不直接写入 canonical memory。

插件不拥有存储、模型供应商、网络权限、专家权威、论文状态或公开发布权。

## 启动所需输入

只有当用户能够提供或确认下列信息时才启动：

1. 目标领域，以及为什么值得付出入域成本；
2. 一个局部现象、命题、机制、数据集或设计问题；
3. 最小相关来源集及其版本或日期边界；
4. 可接受的证据形式：证明、反例、实验、可执行检查、行为研究或专家判断；
5. 时间、模型、工具和专家成本预算；
6. 一个明确的外部准入入口，或清楚声明当前没有该入口。

如果问题的开放/已解决状态、定义或证据义务无法核对，就停在领域地图阶段，不开始解题搜索。

## 能力循环

### 0. 选择一个可准入案例

最多提出三个候选案例，按以下维度比较：

- 边界是否足够局部，六个月内是否可能形成局部结果；
- 能否验证，是否存在负向测试；
- 是否有文字、方程、图、代码或实验等多种表示；
- 是否容易产生“看起来对、其实错”的结果；
- 领域反馈是否可得，成本多高；
- 对人的学习价值；
- 隐私、同意和 AI 披露负担。

只冻结一个案例，其他标记为 `deferred`，不能暗中并行推进。

### 1. 冻结 Case Charter

记录精确对象、问题、已知/未知状态、允许的主张强度、证据义务、工具边界、成本预算、停止规则和外部准入入口。证明、否证、精确障碍和边界清楚的负结果都可以是对称的成功结果。

### 2. 建立最小领域地图

只建立足以避免“解决错问题”的结构：

- 核心对象和定义；
- 表示映射与不变量；
- 典型例子和已知反例；
- 主要方法家族和已记录的失败模式；
- 验证工具与领域评价标准；
- 尚未解决的不确定性，并为每项附来源或专家问题。

AI 的流畅解释不能自动关闭不确定性。

### 3. 运行认识论上不同的搜索

使用证据义务不同的角色，而不是装饰性人格：

| 角色 | 必须产生的贡献 |
|---|---|
| Encoding / reframing | 等价表示，以及问题未被偷换的检查 |
| Constructive | 证明、机制、算法、模型或实验候选 |
| Counterexample / adversarial | 最小攻击、边界条件、循环依赖或竞争性解释 |
| Formal / computational | 可执行检查、形式化子主张、有限搜索或独立实现 |
| Historical / provenance | 邻近工作、既有路线、优先权与新颖性风险 |
| Pedagogical / reconstruction | 另一人可以重建并接受追问的解释 |

在每条路线暴露真实候选、障碍或失败之前保持独立。Agent 更多、输出更长，都不等于认识论多样性。

### 4. 维护 Candidate Ledger

每个实质候选至少记录：

- 候选 ID 和父子谱系；
- 精确主张及适用范围；
- 产生它的角色、模型/工具和来源依赖；
- 已做测试和结果；
- 已知缺口、反证和未解决假设；
- 人的 disposition：`accept`、`revise`、`reject` 或 `defer`，以及理由；
- 时间、调用次数、专家分钟数和其他实质成本。

不能为了让最终路线显得干净而删除失败路线。

### 5. 生成 Admission Receipt

候选只有在准入回执明确区分下列内容后才能晋级：

- `T+`：语义保持变换下，结果应保持什么；
- `T-`：最小语义破坏下，结果应按什么方向改变；
- 独立证据：新模型实例、独立实现、形式系统、外部数据或领域专家是否真正增加了不同约束；
- 来源谱系和新颖性状态；
- 与最强实用基线之间成本和 coverage 匹配的比较；
- 剩余不确定性和校准后的弃权。

形式化只检查被形式化的对象，不能单独证明它对应原问题、具有新颖性或对领域重要。第二个模型若共享同一提示、来源或失败模式，也不能自动算独立证据。

### 6. 分开测试保持与迁移

不能从当场协作表现反推学习。

- 人的保持：AI 介入前记录人的问题模型和未知；之后检查无辅助重建、错误诊断、延迟保持和相邻未见案例迁移。
- 系统保持：使用新模型实例和冻结、可检查的 Case Pack。若成功依赖原完整对话，只能称为 `context-dependent assistance`，不能称为系统学习。
- 领域结果：正确性、新颖性、有用性和独立复现，与人或系统的保持分别报告。

### 7. 结算案例

Case Settlement 必须给出四个相互独立的判断：

1. 领域结果和准入状态；
2. 人的保持与迁移状态；
3. 新系统实例的保持与迁移状态；
4. 工作流的价值、成本和失败模式。

下一状态只选一个：`close`、`revise`、`continue`、`defer` 或 `promote for human review`。送审不等于 canonical acceptance，也不等于公开发布。

## 证据阶梯

| 等级 | 最低证据 | 允许表述 |
|---|---|---|
| E0 instrumented case | 可重建的 charter、ledger、成本、失败和闸门 | 一个可回放的人机科研案例 |
| E1 admission effect | 相对强且成本匹配基线的准入增量 | AI 评价或搜索的局部方法结果 |
| E2 retention / transfer | 撤架、延迟和未见任务表现 | 人或系统保持的有边界证据 |
| E3 domain result | 领域独立判断正确性、新颖性与有用性 | 有明确范围的领域贡献 |
| E4 cross-domain recurrence | 至少两个实质不同领域中的可比证据 | 可迁移入域能力的初步证据 |

不能用一个案例同时包装全部五个等级。

## 停止与回退条件

出现下列情况时停止、缩小或回退：

- 问题状态或证据义务仍不可核验；
- 匹配模型调用、墙钟时间、coverage 或专家劳动后，增益消失；
- 角色只改变措辞，没有改变候选、测试或决定；
- 目标领域无法判断变换是否保持语义；
- 保持只存在于原始聊天上下文；
- 审计成本高于它避免的错误或恢复负担；
- 私有来源、人物数据、未公开主张或发布权将进入公开产物。

回退只移除已安装的任务贡献，保留用户来源和任何已经单独审核的 canonical 记录，不改写或删除研究历史。

## 运行时边界

报告中的原型与可下载版本共享同一能力内核：

```text
public-safe 工作流 + public-safe Case Pack
        + 用户提供的来源与约束
        + 宿主 ResearchOS 的判断与 Review 流程
        = 一次运行时实例
```

在报告中的原型里，所有者历史和私有证据可以改善选题与判断，但仍只是私有输入。在可下载版本中，使用者提供自己的材料与专业性。插件绝不能暗示：原型所有者的能力、身份、合作者或项目事实会随可下载版本一同迁移。

## 输出合同

使用[跨域科研入域 Case Pack](../../09_templates/cross-domain-scientific-entry-case-pack.zh.md)。完整产物包括：

1. Case Charter；
2. Case Selection record；
3. Minimum Domain Map；
4. Approach Registry；
5. Candidate Ledger；
6. Admission Receipt；
7. Human/System Retention Report；
8. Transfer Report；
9. Case Settlement。

所有判断在指定的人或领域权威通过宿主系统的 Review 路由确认前，都保持 candidate-only。
