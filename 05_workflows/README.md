# Workflow Layer

Stores reusable public workflows such as material intake, candidate confirmation, agent handoff, validation, and self-evolution. Everyday research work, such as reading a paper, writing, reviewing, a grant proposal, a meeting follow-up, feedback to a mentee, a change of topic, or a talk or figure, has short methods in [`research_work/`](research_work/README.md); each names the cards an assistant reads at each level and the route id `plan_context.py` takes. Core workflows live in `research_management/`:

- `material-intake-workflow.md`: M1 intake for new material.
- `asset-type-extension-workflow.md`: extension workflow for new asset classes, resource objects, workflow objects, or dashboard boxes.
- `material-analysis-lifecycle-standard.md`: M1/M2/M3 material maturity.
- `task-to-context-matrix.md`: task-to-context routing.
- `ai-agent-collaboration-workflow.md`: collaboration protocol for user, Codex GUI/CLI, and other agents.
- `group-composition-lifecycle-standard.md`: G0/G1/G2 card grouping and relation-card standard.
- `new-project-intake-workflow.md`: early idea and project seed intake.
- `research-expression-engine-playbook.md`: writing, talk, proposal, figure, and public narrative workflow.
- `self-evolution-workflow.md`: ResearchOS self-audit and candidate improvement workflow.
