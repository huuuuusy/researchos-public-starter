# ResearchOS Public Starter V1.1

状态：候选版本 `1.1.0-rc.1`；最新发布版是 2026-11-07 发布的 `v1.0.4`。

1.x 系列是 ResearchOS 的第一阶段：一位研究者、本机文件、终端上的决定。这一版没有新功能。它把第一阶段包含什么、不包含什么集中写在一处，并修正了发布后代码审查查出的若干问题，逐条列在下面。

## 第一阶段包含什么

- 一次会话的六条命令：`ros today`、`context`、`run`、`collect`、`admit` 和 `close`。判断写下时记住它依据的来源文件与版本；其中某个文件一变，下一条命令就把这条判断交回研究者。
- 两种运行方式。在本仓库里，`ros admit` 显示拟议的改动，由你自己贴进去，再在你的终端上用 `ros admit --confirm` 确认；随附的 `config/ros.json` 保持 `runtime_scope: public_starter`。在报告描述的原型里，研究者在终端上确认后由系统写入。
- 描述这一阶段的技术报告 V12。

## 第一阶段不包含什么

技术报告的补充说明 6 逐条列出第一阶段的范围边界。其中包括：在原型里，由 Agent 执行准入或重新确认时，改动照样写入，只记为调用者的断言；Dashboard 的写入不经过准入；判断的依据按文件记录，不细到某一条论据；变化在命令运行时才被察觉，没有命令运行时察觉不到；变化不会沿依赖跨多步传下去；与更简单做法的比较和使用研究都还没有做。目前作者是唯一用户，报告不主张科研收益。

## 本版修正

`v1.0.4` 之后代码审查查出的问题：

- `ros propose judgment --target` 只接受扫描范围内的卡片；以前扫描范围外、甚至库外的目标也会被接受，`ros admit` 会打印出那个文件的内容。
- `candidates.jsonl` 追加前先截掉半截的末行；末行之前若有损坏的行，会报错而不是悄悄跳过。以前下一条候选可能丢失。
- 必须由研究者在终端上作答或决定时，打印出的命令对 `cancel` 和 `satisfied` 补上了 `--reason <理由>`。
- 你上传的文件名为 `*.tmp` 时，Dashboard 启动时不再把它删掉；只清理上传过程自己留下的临时副本。
- 本地运行日志里有一行损坏，不再让 `/codex-runner` 或服务器启动失败。
- 公开 Dashboard 中，`/data/` 不再列出文件夹内容；服务器测试改为检查每个检出里都有的文件。
- `personal_vault/` 里不是 UTF-8 编码的笔记，会在构建失败信息里点名，不再抛出堆栈。
- `start_researchos.py --mode personal-vault --check` 会报告本机是否装了命令行工具，手册改为指向这条命令。
- 首次上手说明和 `AGENTS.md` 写明：你手动改过的判断类字段由 `close` 列出，之后由 `today` 列出。

实现没有达到自身定义的三处（V11 补充说明 6 的第 6、18、23 条）：

- 没有标敏感级别的来源，`ros context` 不再按 internal 交付，而是排除，理由记为 `sensitivity:unlabeled`，与「无法识别的级别一律排除」这一规则一致。随附的模板和演示卡片都标了级别；你自己的卡片如果没有，加一行 `sensitivity:`，`ros context` 才会交付它。
- 问题预算用尽、而某个问题是在较早的依据版本上提出的，这个问题会被撤回、相应工作重新打开，会话不会再在过期依据上以 `complete_with_held` 结束。
- 范围不变而内部归属移动时，归因为范围变化，不再归因为来源变化。

[V1.0 发布说明](v1.0.0.zh.md)仍是 V1.0 包含什么的记录。
