# ResearchOS Public Starter V1.0

Status: released as `v1.0.0` on 2026-10-29.

## Release Judgment

V1.0 presents ResearchOS as a coherent public reference tool rather than a snapshot of the private vault.

ResearchOS is a local-primary system for continuously maintaining research state. It connects questions, evidence, judgments, responsibilities and next steps through a researcher-owned authority workflow. Agent/CLI is the primary execution surface; the deliberately narrow local dashboard is a persistent attention and control surface, not an Agent prerequisite or a second authority.

## What Is Included

- A Markdown + repository-aware assistant route with explicit reading, candidate, writeback, and validation boundaries.
- A compact Unified Desk for selecting an item, previewing attention dates, inspecting its components, and previewing or copying an agent handoff. Now and Library are two areas of the same desk.
- Existing Agent/CLI and Work Session contracts for bounded research tasks. The current desk exposes item-bound handoff preview and copy as its visible execution entry; the public runtime starts no provider.
- `answer`, `artifact` and `writeback` result contracts; public durable-change output is a copyable candidate, not enabled admission or canonical writeback.
- Cards as optional bounded context rather than a mandatory home-page wall.
- Markdown, project, relation, and PDF preview surfaces.
- Fictional public demo data and a local `personal-vault` projection route.
- Separate workflow, evidence, sensitivity, and authority states.
- English and Chinese documentation, routing guides, templates, validators, and GitHub community files.
- A dated, non-ranked bilingual guide to adjacent research tools and wider resource collections; it is a reference snapshot, not an endorsement or continuous-update promise.
- A credential-free, copy-only public runtime that starts no local CLI and has no remote API provider. (The optional `--mode personal-vault` route is a separate, controlled Dashboard mode that can start a locally installed Codex CLI; the default public mode never does. It does not change `ros`.)
- Shared kernel source, contracts and synthetic regression cases for inspection. `python3 scripts/ros_demo.py` demonstrates kernel behavior in a temporary fictional repository; attention scheduling, admission writeback, maintenance writes and completion records remain private-prototype workflows; the public `ros.py` runs `today`, `context`, `run … --executor copy_packet`, `collect` and `close` on fictional material (`--root examples/scheduler-demo`), writes only git-ignored working records, and refuses canonical admission and provider dispatch. This copy-only behavior is set by `runtime_scope: public_starter` in the shipped `config/ros.json`; [Section 3 of the User Manual](../user-manual.en.md#3-the-session-scheduler-and-command-line-checks) describes each command, `admit --confirm` and the `runtime_scope` rule.
- Three bundled task-extension examples (`method_comparison`, `cross_domain_scientific_entry` and `codex_thread_handoff`) and a local, reversible plugin lifecycle. The plugin system is frozen: inclusion permits inspection and existing examples, not active feature development or a commitment to future capabilities; it grants no network or canonical-write authority.
- Bilingual technical report: Sections 1–5 and Appendices A–B, with a 39-page [English PDF](../technical-report.en.pdf) and a 33-page [Chinese PDF](../technical-report.zh.pdf). [Supplementary Notes 1–6](../technical-report-supplement.en.md) are supplied separately and do not enter the PDFs; of the 137 bibliography entries in each PDF, 101 are cited only in the Supplementary Notes. The report describes the private prototype, does not extend the public runtime, and has not been peer reviewed.

## First Run

The primary route is to open the repository in Codex, Claude Code, Gemini CLI, or another file-aware client, read `AGENTS.md`, and state one task with its source and sensitivity boundary.

The optional dashboard demo requires Python 3.10 or newer (on Windows, inside WSL) and a modern browser; platform details are in the [README](../../README.md):

```bash
python3 scripts/start_researchos.py --mode dashboard --port 8880
```

Open `http://127.0.0.1:8880/`. The dashboard shows a single Unified Desk: select a task card, preview attention dates in the calendar, inspect its linked components in the right-hand rail, and copy an agent handoff. Public drag actions are previews, and copying a packet neither runs a provider nor writes canonical files. Neither Work nor Review is a third screen; both open inside the selected item.

## Public Boundary

This release does not contain private research memory, unpublished manuscripts, real relationship notes, provider credentials, private runtime logs, raw corpus payloads, personal machine paths, or sibling private-system integrations. The public dashboard produces copyable task packets and may create a browser-local Review proposal, but it starts no executor, cannot write private/canonical Markdown, and rejects arbitrary commands.

Do not add private material to a clone that you still push to a public repository. Create a local-only copy or private repository before using `personal-vault` with real material.

## Known Limitations

- The current evidence is repository validation and one researcher's autobiographical design use, not a controlled multi-user study.
- The dashboard is deliberately narrow and does not claim the breadth, polish, or accessibility coverage of mature research products.
- Task-conditioned card suggestions still require some manual search and curation.
- Durable writeback and the live diagnostic chain remain outside this copy-only public edition.
- Resume packets are not generated automatically for every task and client.
- Windows and Linux file bridges have automated coverage but not the same native visual acceptance pass as macOS.
- This is a local reference tool, not a hosted service, polished product, autonomous scientist, or production multi-user platform.
- The plugin validator shipped here (`validate_plugin_standard.py`) is the public variant; the private prototype's copy also checks capability groups that only the private registry carries. The plugin system is frozen in both editions.
