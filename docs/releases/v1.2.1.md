# ResearchOS Public Starter V1.2.1

Status: release candidate `v1.2.1-rc.1`, not yet released. The release date is added on release.

The 1.x series is the first stage of ResearchOS: one researcher, local files, decisions at the terminal. This release rewrites the User Manual in the order a reader actually uses ResearchOS, and fixes two places in `ros` output that a novice walkthrough of the new manual found hard to follow. The rules for judgments and admission are unchanged.

## Changed

- **The User Manual follows your progress.** Instead of one section per part of the system, it now goes step by step: what this repository is (with the five-minute demo and the words you will meet), building your own vault, the first source change, letting the vault grow, and working style with maturity and the vault check. A sixth section collects other ways to use it (a browser chat only, the Dashboard, picking up after a break), and five appendices hold the command and field reference, replacing a judgment, safety, what the first stage covers, and notes for maintainers. Each step says what you will use, what to do, what you should see and what you can do afterwards; commands are whole lines to copy, and the output shown is taken from real runs. Section 3 still holds the session commands from `today` to `close`. No caveat was dropped; an independent audit compared the old and new manuals sentence by sentence.
- **A deferral run by an assistant says it is not in effect.** When an assistant runs `ros decide <id> defer` without a terminal, `ros` now says the deferral is not in effect, that only your own confirmation at the terminal defers the item, and which line to run. The item stays listed in `today`, `today --all` and `close`. Before, it was hidden from `today` while `close` still counted it, and the count line printed an empty commitment name.
- **`admit` prints text you can paste.** After the diff, `ros admit` and `ros admit --reconfirm` print the text to paste into the commitment list and say where it goes: which lines to replace, or after which line to insert. The diff stays for checking. The prototype, which writes the change itself, is unchanged.
- The card skeletons and the example-card READMEs say that paths in `related_*` and `source_files` are counted from the root of the vault.
- Links and section numbers that point into the manual are updated across the README, `AGENTS.md`, the System Reference, the Governance and Extension Guide, the first-run guide and other entry files. The Dashboard's quick-route note in a task packet now points to Section 4 of the manual (an approved one-line change in frozen code, recorded in the prototype's freeze register).

The technical report V12 describes `v1.1.0`; this release does not change it.
