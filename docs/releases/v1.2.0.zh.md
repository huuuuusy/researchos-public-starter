# ResearchOS Public Starter V1.2

状态：候选版 `v1.2.0-rc.1`，尚未发布。正式日期在发布时填写。

1.x 系列是 ResearchOS 的第一阶段：一位研究者、本机文件、终端上的决定。这一版补上的是卡片怎样写、助手怎样按层读你的卡；`ros` 接上了注意力安排，其余只改了新手实跑查出的几处说法和提示，判断与准入的规则不变。原型里的这些做法以前只体现在作者自己的材料里；现在本仓库里每一项都有一份填好的示例、一份空白骨架和一条能运行的命令。

## 新增

- **按层读你自己的卡。** `python3 scripts/plan_context.py <任务> --vault personal_vault --mode quick|standard|evidence`，库是中文时自动用中文：quick 读这类任务的风格卡（对外任务先读边界卡），没有就读研究身份摘要；standard 再加研究身份摘要、这类任务的工作流、方向摘要，并列出方向摘要点名的卡，由助手用 `ros context` 逐张取；evidence 再加成果与使用边界、论文作者角色两张索引，并只开这些卡「证据边界」里写明的原件，而且要有一个说得出的核对问题。你的库里还没有的卡会被点名，并给出从哪份骨架开始。每一档还写明默认不读什么、什么时候升级。
- **示例卡与骨架。** `examples/starter-cards/en/` 和 `zh-CN/` 有十二张虚构的卡，讲同一件事：研究身份摘要、边界卡、方向摘要、项目、论文、成果与使用边界、决策、启发式、写作风格卡、人物、论文作者角色和会议。`09_templates/basic/` 是同一套卡的空白骨架，另有审稿意见、基金申请、学术邮件、给学生的反馈和心智模型。较早的完整模板与骨架是同一张卡，只多出后期才用得上的小节。
- **风格卡从纠正里长出来。** `03_cognition/style/` 下每类任务一张（写作、审稿、申请、报告与配图、指导学生）。每一条写规则、为什么、怎么用和出处；你纠正助手时，它把这次纠正起草成一条，你同意后才加进去。
- **边界卡。** `00_identity/boundaries.md` 用你自己的话写：哪些材料从不交给助手，哪些事对外不说，机构、伦理委员会或期刊对 AI 工具的规定，以及发出去之前要谁点头。对外的任务（外部请求、申请、报告、审稿、导出）先读它。
- **九份研究工作流。** `05_workflows/research_work/`：读论文、写论文、审稿、写申请、会议跟进、给学生反馈、要不要换题、报告与配图，以及复盘：把一次教训写成启发式卡或风格卡的一条。新增三条路由 `peer_review`、`meeting_follow_up`、`mentee_feedback`。
- **库体检。** `python3 scripts/build_public_starter_data.py --personal-vault` 的试运行会报告断开的链接、无法识别的敏感性标签、空的 Agent Summary、frontmatter 行尾的 `#` 注释、比所列卡片更旧的方向摘要，以及本机找不到的原件。它只读，不改任何文件。
- **注意力安排。** 你决定某项承诺什么时候做时，`ros attend <承诺> today|tomorrow|date|park|complete-step` 给出要放进 `06_active_context/work_state/attention-schedule.md` 的条目；贴进去之后，`today` 在「今日」下列出排在今天的承诺。按本仓库的规则，`ros` 不写这个文件，由你或你同意后的助手贴入；模板在 `09_templates/attention-schedule.zh.md`。
- **给网页聊天的卡片包。** `python3 scripts/plan_context.py <路线> --vault personal_vault --pack <文件>` 把这一档要读的卡拼成一份可以直接粘贴的文本，只放 public 和 internal 的卡，并列出没放进来的卡；不会写进本仓库的受跟踪文件。

## 改动

- 首次上手把论文、项目和摘要卡写成 `internal`，个人档案和合作者卡写成 `sensitive`。以前一律写成 `private`，而 `ros context` 从不打包 `private`，所以交不出用户自己的任何一张卡。
- 首次上手多了一步：研究身份摘要和一份方向摘要。`AGENTS.md` 新增「首次上手之后的每次会话」：开始跑 `today`，结束跑 `close`；事实直接写，判断用 `ros propose` 提交、由你在终端确认。
- `ros_demo.py --init` 把 `02_decisions` 和 `03_cognition` 加进库的扫描范围；中文库里的虚构承诺是中文。
- `query_research_agenda.py` 在 `personal_vault/` 存在时默认读它，库是中文时摘要行也是中文。
- 成熟度只在一处讲（卡片成熟度量表），等级示例改用卡片实际使用的字段。
- 手册说明 Dashboard 在个人库模式下显示哪几类卡，并为只用浏览器聊天的读者加了一节：没有终端时来源变化后的复核用不上，卡片的分层读法仍然可用。

两位没用过终端的研究者按首次上手实跑之后改的 `ros` 输出：

- 中文库里，`ros context` 询问是否交出敏感卡时用中文；卡被排除时，每张都写明原因和接下来怎么做（sensitive 卡要你在自己的终端运行同一条命令并确认，内容印在你的终端里）。
- 删掉判断块后的提示不再说「从 Git 恢复」，改为从你自己的备份恢复（`personal_vault/` 不在 Git 里）。
- `today` 的计数行改成白话：「待办」按本次会话的未关闭事项计，其中不在「待判断」下的会写明在哪里、用 `today --all` 能看到；「待判断」「今日」按承诺计。范围外的事项和三类未知只在不为零时出现。
- 替换一条判断后，`close` 还会列出一项直接改动的 `judgments` 字段，这是设计：手工改动要单独确认，确认判断块不算确认这一行。现在提示写明原因，并给出带真实编号的 `ros decide <编号> confirm`；已经事后确认过的候选不再列为「未决」。
- 旧复核的「narrow」选项改名为「这条事项保持未关闭，留到下一个版本（延期）」；「收窄」只指收窄一条判断。
- 会话中途写下的判断块算进本次会话：它没确认时，`close` 不会报告完成，`today` 也不再把它算作范围外。
- `close` 的结果先用白话说，例如「由你收尾，仍有未关闭的工作（human_stopped）」，括号里保留原来的结果名，`--json` 不变。
- 公开安装里如果把 `runtime_scope` 改成 `private`，`ros attend` 会说明这是原型的设置、本仓库不支持，什么都不写，不再报技术错误。
- 一项承诺即使搁置、改到以后或在等待，只要它的依据变了，`today` 也会把它列在「待判断」下，不会藏起来。
- 等你确认的事项，`today` 和 `close` 列出的是同一组；会话收尾之后再收尾，会用中文说明先运行 `today` 开新会话。
- `close` 的输出更好读：只给短编号，不再露出整串哈希；范围那一行只在需要时或加 `--all` 时出现；表头的数目和下面列出的条数一致。
- 判断已被替换后，旧复核的选项把「取消」排在第一，「确立不满足」改为「仍不成立」；敏感卡的确认提示改为「在这里显示这张敏感卡片？」。
- 输出和文档里，`research-portfolio.md` 统一叫「承诺清单」。

Dashboard 的两处修正，按冻结登记里的批准记录改：个人库模式下不再显示「虚构演示」的建卡面板（它在这里不会写入任何文件）；材料流程插件给卡片的敏感性默认值改成和首次上手一致。

README 写的首次上手用时改为半小时到一小时，与两次实跑一致。

README 和手册重写了几处：第 2 节去掉工程术语（技术细节移到系统参考），README 按实际用法讲日常命令（加上 `propose`），说清 `ros` 不写卡、可选的 Dashboard 在你确认后才写，局限集中成一段，面向读者的文字统一用「库」「演示库」。README 里的会话动图按现在的输出重新生成。

中文演示改用中文的演示库（`examples/scheduler-demo-zh/`），判断、问题和卡片标题都是中文。`plan_context` 的中文输出不再夹英文；卡片包附上这些卡所属的承诺和当前判断，做法说明里去掉了浏览器里没法执行的命令。库体检按库的语言输出，没写文件时也不再印输出路径。手册又做了一轮通读修改：模式对照表、词表和几处术语改成白话，论文骨架也适用于问卷、档案目录和数据集，示例卡说明了怎样换成社会科学和人文研究。README 里的三张动图按现在的输出和用词重新生成。

技术报告 V12 描述的是 `v1.1.0`，这一版不改报告。
