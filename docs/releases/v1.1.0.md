# ResearchOS Public Starter V1.1

Status: released as `v1.1.0` on 2026-11-11.

The 1.x series is the first stage of ResearchOS: one researcher, local files, decisions at the terminal. This release adds no features. It states in one place what the first stage includes and what it leaves out, and corrects the problems found in the post-release code review, each listed below.

## What the first stage includes

- The six commands of a session, `ros today`, `context`, `run`, `collect`, `admit` and `close`: a judgment is written down with the source files and versions it rests on, and when one of those files changes, the next command hands the judgment back to the researcher.
- Two ways of running it. In this repository `ros admit` shows the planned change, you paste it in yourself, and you confirm it at your terminal with `ros admit --confirm`; the shipped `config/ros.json` keeps `runtime_scope: public_starter`. In the prototype described in the report, the system writes the change after the researcher confirms at the terminal.
- Technical report V12, which describes this first stage.

## What the first stage does not include

Supplementary Note 6 of the technical report lists the boundary of the first stage item by item. Among them: in the prototype, when an agent runs admission or reconfirmation, the change is still written and only recorded as asserted by the caller; Dashboard writes do not go through admission; a judgment's basis is a file, not an individual argument; a change is noticed when a command runs, not while none is running; a change is not followed across several dependency steps; and neither a comparison with simpler practice nor a study of use has been run. The author is the only user so far, and the report claims no research benefit.

## Corrections in this release

Found in the code review after `v1.0.4`:

- `ros propose judgment --target` accepts only a card in the scanned graph; a target outside it, even outside the vault, was accepted, and `ros admit` printed that file's contents.
- `candidates.jsonl` drops a torn last line before appending, and a damaged line before the last one is reported instead of silently skipped; previously the next candidate could be lost.
- When an answer or decision must be given at the researcher's terminal, the command it prints now includes `--reason <reason>` for `cancel` and `satisfied`.
- A file you upload that is named `*.tmp` is no longer deleted when the Dashboard starts; only the uploader's own partial copies are.
- A damaged line in the local run log no longer stops `/codex-runner` or the server's startup.
- In the public Dashboard, `/data/` no longer lists the folder; the server test now checks a file that exists in every checkout.
- A note in `personal_vault/` that is not UTF-8 is named in the build failures instead of ending in a traceback.
- `start_researchos.py --mode personal-vault --check` reports whether the local CLI is installed, and the manual points to it.
- The first-run guide and `AGENTS.md` say that a judgment-class field you change by hand is listed by `close`, then by `today`.

Found when the first run was walked again by a researcher new to terminals, and the output read as daily text:

- `--lang` works after the command as well as before it, and a vault started with `--lang zh-CN` needs no flag afterwards.
- The first-run judgment template no longer names the commitment as a basis, so updating the commitment's dates or next step does not send the judgment back for recheck.
- When a deadline is today or past, the "On track" option, whose deferral `ros` would refuse, is no longer offered; "Keep as is" is now "Stop reminding me about this date".
- `today` puts what needs a decision first: the open items a change touches are listed once, under "To decide"; the scope and unknowns lines appear only when one of them is not zero, and the budget line only once the budget is spent; in this repository the Today section is left out when it is empty, and so are the `attend` proposals, which `attend` cannot carry out here. `today --all` and `--json` still give everything.
- `admit` ends with the next step after the printed change; `close` no longer contradicts itself, its confirmation, removal and pending-candidate lines say what to do, and its judgment template bases a judgment on cards.
- The output uses the report's terms: item, open, waiting on your answer and deferred. A question about a judgment that is gone says so in words, and three common refusals are translated.
- The manual has a "When a source changes" section, the first-run guide and `AGENTS.md` point to it, and the glossary adds vault, research graph and fixture. README and the Chinese documents are shorter and read more naturally; every limitation they stated is kept.

Three places where the implementation fell short of its own definitions (items 6, 18 and 23 of Supplementary Note 6 in V11):

- A source without a sensitivity label is no longer delivered as internal by `ros context`; it is excluded with `sensitivity:unlabeled`, as the rule for unrecognized levels requires. The shipped templates and demo cards all carry a label; if a card of your own has none, add a `sensitivity:` line so that `ros context` delivers it.
- When the question budget is spent and a question was asked on an earlier basis version, that question is withdrawn and the work reopens, so a session can no longer end `complete_with_held` on an obsolete basis.
- An ownership move inside an unchanged scope is attributed to the scope, not to a source change.

[V1.0 release notes](v1.0.0.md) remain the record of what V1.0 includes.
