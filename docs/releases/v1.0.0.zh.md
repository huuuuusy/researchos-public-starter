# ResearchOS 公开 starter V1.0

发布状态：已于 2026-10-29 以 `v1.0.0` 发布。

## 发布判断

V1.0 把 ResearchOS 作为完整的公开参考工具呈现，而不是把私人库截面搬出来。

ResearchOS 是一个持续维护研究状态、本地为主的系统。它通过研究者拥有的权威工作流，连接问题、证据、判断、责任与下一步。Agent/CLI 是主要执行面；刻意收窄的本地 Dashboard 是持续注意力与控制面，不是 Agent 的前置条件，也不是第二套判断权威。

## 包含内容

- 带有明确读取、候选、写回和验证边界的 Markdown + repository-aware assistant 路线。
- 使用虚构数据的统一工作台：选择事项、预览关注日期、在事项详情中查看组件，再预览或复制 Agent 交接。`现在`与`资料`是同一工作台上的两个区域。
- 现有 Agent/CLI 与 Work Session 合同支持有边界的研究任务；当前工作台的可见执行入口是事项内交接预览与复制，公开运行态不启动 provider。
- `answer`、`artifact`、`writeback` 结果合同；公开版的长期变化输出是可复制候选，不启用准入或正典写回。
- 卡片作为按需、有边界的上下文，而不是首页必须先理解的卡片墙。
- Markdown、项目、关系和 PDF 预览能力。
- 虚构公开 demo 数据与本地 `personal-vault` 投影路线。
- 相互分离的工作流、证据、敏感度和权威状态。
- 中英文文档、路由指南、模板、验证器和 GitHub 社区文件。
- 有日期、无排名的中英文相邻科研工具与更广资源清单；它是参考快照，不是背书或持续更新承诺。
- 无需 API key 的 copy-only 公开运行态，不启动任何本机 CLI，也没有远程 provider。（可选的 `--mode personal-vault` 是另一条受控的 Dashboard 模式，可能启动本机已安装的 Codex CLI；默认公开模式绝不会。它不改变 `ros`。）
- 可阅读的共享内核源码、合同与合成回归案例。`python3 scripts/ros_demo.py` 在临时虚构仓库中演示内核行为；注意力安排、准入写回、维护写入和完成记录仍属于私有原型工作流；公开 starter 的 `ros.py` 在虚构材料上运行 `today`、`context`、`run … --executor copy_packet`、`collect` 与 `close`（`--root examples/scheduler-demo`），只写 git 忽略的工作记录，拒绝准入长期来源与 provider 派发。这一只复制行为由出厂 `config/ros.json` 中的 `runtime_scope: public_starter` 设定；各命令、`admit --confirm` 与 `runtime_scope` 规则见[用户手册第 3 节](../user-manual.zh.md#3-会话调度器与命令行检查)。
- 三个随附的任务扩展示例（`method_comparison`、`cross_domain_scientific_entry` 与 `codex_thread_handoff`）及本地、可逆的插件生命周期。插件体系处于冻结状态：随包保留用于阅读和已有示例，不表示积极开发新功能或承诺后续能力，也不授予联网或正典写回权。
- 双语技术报告：正文第 1–5 节与附录 A–B，[英文 PDF](../technical-report.en.pdf) 为 39 页，[中文 PDF](../technical-report.zh.pdf) 为 33 页。[补充说明 1–6](../technical-report-supplement.zh.md) 单独提供，不进入 PDF；PDF 书目共 137 条，其中 101 条只在补充说明中引用。报告描述私有原型，不扩展公开运行能力，未经同行评审。

## 首次使用

主要路线是在 Codex、Claude Code、Gemini CLI 或其他文件感知客户端中打开仓库，先读 `AGENTS.md`，再说明一个任务、来源和敏感性边界。

可选的 Dashboard demo 需要 Python 3.10 或更高版本（Windows 须在 WSL 中运行）和现代浏览器；平台说明见 [README](../../README.zh.md)：

```bash
python3 scripts/start_researchos.py --mode dashboard --port 8880
```

打开 `http://127.0.0.1:8880/`。Dashboard 使用单一统一工作台：选择事项卡，在日历中预览关注日期，在右侧查看关联组件，再复制 Agent 交接任务包。拖拽只产生预览，复制任务包不会启动 provider，也不会写回 canonical 文件。Work/Review 都不是第三个顶层屏幕，只在所选事项内展开。

## 公开边界

本版本不包含私人研究记忆、未公开论文、真实关系笔记、provider 凭据、私人运行日志、raw corpus payload、个人机器路径或私人 sibling-system 联动。公开 dashboard 只生成可复制任务包，也可以建立仅保存在浏览器中的待复核候选；它不启动本机 Codex 或远程 provider，不能写入私人/canonical Markdown，并拒绝任意命令。

不要把真实私人材料加入仍会推送到公开仓库的 clone。使用 `personal-vault` 处理真实材料前，应先建立 local-only 副本或 private repository。

## 已知局限

- 当前证据来自仓库验证和单一研究者的 autobiographical design 自用，不是受控多用户研究。
- Dashboard 被刻意收窄，不声称达到成熟科研产品的功能广度、精致程度或可访问性覆盖。
- 任务条件卡片建议仍有一部分依赖人工搜索和选择。
- 长期写回与实时诊断链不在本次只复制的公开 starter 范围内。
- resume packet 尚未自动覆盖所有任务和客户端。
- Windows/Linux file bridge 有自动化覆盖，但尚未完成与 macOS 同等的原生视觉验收。
- 这是本地参考工具，不是托管服务、成熟产品、自治科研系统或生产级多用户平台。
- 随本仓发布的插件校验器 `validate_plugin_standard.py` 是公开变体；私有原型的副本还检查只有私有注册表才带的能力分组。两个版本中的插件体系均处于冻结状态。
