# 贡献指南

感谢你考虑贡献。ResearchOS Public Starter 接受公开安全的文档、示例、模板、验证脚本、仪表盘行为和 copy-only 交接界面改进。

## 可贡献范围

适合贡献的内容包括：

- 更清晰的文档；
- 公开安全的示例案例和模板；
- 仪表盘可用性改进；
- 能发现不安全导出、文档断链或配置漂移的验证脚本；
- copy-only 交接与 fail-closed 能力改进；
- 带可复现本地命令的问题报告；
- 不暴露敏感材料的非商业工作流示例。

## 公开安全规则

在提交问题或拉取请求前，请使用虚构或已脱敏的示例，并确认内容不包含：

- 真实敏感人物、学生、合作者、评审或关系笔记；
- 私人研究记忆或其他个人数据；
- 未发布论文、保密项目计划或原始语料；
- 模型密钥、令牌、凭据或账号标识；
- 本地绝对路径或机器相关运行日志；
- 被当成确定知识的未经审核智能体输出；
- 与许可边界冲突的商业分发说明。

贡献必须遵守[许可](../../LICENSE.md)和[商业使用边界](COMMERCIAL_USE.zh.md)。安全漏洞请按[安全政策](SECURITY.zh.md)报告，不要发公开问题。

## 文档标准

- 根目录文档保持简洁。
- 详细说明放入[文档地图](../README.zh.md)中对应问题的现有 owner。
- 关键公开文档使用独立英文文件和中文文件。
- 用具体命令和路径说明操作，避免笼统建议。
- 说明判断权边界：来源材料、候选解释、确认、验证和导出是不同层级。
- 示例宜小不宜大，避免塞入大型样例数据。

## 本地检查

提交拉取请求前，逐条运行 `.github/workflows/validate.yml` 中的步骤，即本仓库的 CI。`CITATION.cff` 已写入发布日期，所以 `validate_release_metadata.py` 按正式发布校验，不带 `--expected-commit` 与 `--require-clean` 就会失败；在本机先提交改动，再在没有未提交改动的工作树上运行 `python3 scripts/validate_release_metadata.py --expected-commit "$(git rev-parse HEAD)" --require-clean`。

如果修改了文档，请确认文档地图仍指向正确文件。如果修改了模型提供方或启动模式，请同步更新 `docs/user-manual.zh.md` 和 `docs/user-manual.en.md`。

## 问题和拉取请求建议

一个有用的问题报告应包含：

- 操作系统和 Python 版本；
- 你运行的命令；
- 预期行为；
- 实际行为；
- 必要时提供已脱敏的短日志；
- 案例材料是开启还是关闭。

一个有用的拉取请求应包含：

- 简短说明它解决的用户问题；
- 修改了哪些文件；
- 运行了哪些检查；
- 有哪些公开安全假设；
- 只有在界面行为变化时才附截图。

## 维护者审查

维护者可能会要求缩小范围、减少示例、加强公开安全说明或补充验证。这是正常的，因为本项目的价值依赖于研究材料、解释、确认和发布之间清晰的边界。
