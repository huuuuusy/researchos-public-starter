# 卡片成熟度与增强

<p align="right">
  <a href="CARD_MATURITY_AND_ENHANCEMENT.md">English</a> | <strong>中文</strong>
</p>

本文说明 ResearchOS 如何显示卡片成熟度，以及如何把“进一步完善这张卡”转换成一个有边界的任务。第一次使用不需要先读本文。

## 不同卡片不能共用一个模糊等级

资料页中的卡片可以显示一个主成熟度轴，并配通俗中文：

| 卡片 | 等级轴 | 表示什么 |
| --- | --- | --- |
| 论文、报告、来源或笔记 | `M1–M3` | OS 对材料理解到什么程度 |
| 想法或项目 | `I0–I3` | 它从临时判断走到独立项目的哪一步 |
| 人物 | `R0–R3` | 有来源的工作关系资料完整到什么程度 |
| 卡片组合或方向 | `G0–G2 / 研究主线` | 多张卡是否形成可复用组合 |

`P0–P3` 是项目优先级，不是成熟度。生命周期、排期、关系置信度和上下文预算也分别属于其他状态轴。ResearchOS 不给人物价值评级；R 只描述关系资料的完整程度。

## 等级出现在哪里

- **现在**在多项 Commitment 之间分配注意力，不重复完整等级体系。
- **资料**显示主成熟度、直接关联和以卡片为中心的增强预览。
- **推进**区分多个有界 session；其中的**待复核**状态显示返回结果或候选变化，并管理任何长期变化。待复核不是第四屏或通知 Inbox。

这里的事项内位置与结果/候选示例只描述 Review 的部分用途。[完整接收范围](../system-reference.zh.md#共享治理边界)还包括有界未知、break-glass 确认、验证失败、回滚与关闭前必须明确的交接；同一说明区分要求等待/延期与 portfolio 状态，并解释完成与上下文交付。这些定义不在本仓库启用私有写入。

卡片正面最多显示一个主成熟度、一个与当前决定有关的次级状态、一个日期、一条行动信息和一小段关系预览。项目卡最多显示两位已确认人物和 `+N`；候选关系单独呈现。

## 增强卡片

`增强卡片`不会立即改变等级。它打开现有卡片侧栏并显示：

1. 当前等级及来源；
2. 到下一等级最多三个缺口；
3. 有界的已确认直接关联，以及明确标记的候选关联；
4. 一份带读取范围、产物、保存位置和确认要求的任务预览。

任务随后进入`推进`继续或交给 Agent 客户端；返回的结果或候选变化再进入 Work 内`待复核`。执行完成只产生结果和候选变化；经过 Review、用户确认、写回、验证和重新构建后，等级才可能改变。

达到最高成熟度后，来源过期时显示`重新核验`，当前有效时显示`用于当前任务`。等级来自启发式或存在冲突时显示`核对等级`。没有可追溯来源时只允许`补来源`。

## 有界上下文

增强任务默认只读取当前 canonical 卡片、最多五条已确认一跳关系、判断下一等级所需的最多三条候选关系，以及对应成熟度规则。它不会默认扫描全库，也不会在没有明确需要和用户确认时读取 private/sensitive 材料。结果必须报告实际读取、主动未读、剩余缺口和是否建议改变成熟度。

## 公开与个人空间边界

| 能力 | 公开 demo | personal-vault |
| --- | --- | --- |
| 卡片与关系 | 仅虚构数据 | 用户控制的本地材料 |
| 增强预览 | 可以 | 可以 |
| 执行 | 只复制任务包；本仓库 只走复制回退，不向长期来源准入 | 用户明确触发的本地受控执行 |
| 长期变化 | 禁止 | 先形成候选，再由用户确认 |
| 外部下载 | 禁止 | 仅处理用户提供并明确确认的来源 |

公开 demo 不探测私人 provider、不读取私人仓库、不写 canonical memory。共享的 UI 和状态语义不变，只有数据与权限不同。

## 向后兼容

- 现有材料 `upgrade` 候选兼容映射为 M 轴的 `card_enhancement`。
- 现有 `Person-M1–M3` 视图数据兼容映射为关系资料 `R1–R3`，不能解释为人物价值。
- 项目缺少显式 I 成熟度时显示`待核对`，不得根据 priority、active、排期或文件数量猜测。
- 增强复用现有 CandidateEnvelope、处理和 Review，不新增另一套 Inbox、第四屏或关系图工作区。

## 可访问性与验收

等级必须包含文字，不能只靠颜色。截断标签和关系在鼠标 hover 与键盘 focus 时显示完整值。手机端至少保留一位人物和 `+N`，且不能横向溢出。如果用户把成熟度和优先级混淆、把关系资料理解成人物价值，或以为增强会立即写入长期状态，就不能视为验收通过。
