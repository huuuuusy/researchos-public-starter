# 安全政策

ResearchOS Public Starter 是本地优先的启动项目，但仍可能出现安全相关问题，例如不安全示例、密钥误暴露、模型提供方配置错误、生成数据泄漏或公开导出检查不足。

## 支持范围

安全报告应聚焦当前公开启动包，包括：

- 仪表盘文件和本地服务器行为；
- 运行配置示例；
- 模型提供方注册表、本机限定执行和只读沙箱保护规则；
- 公开 demo 的只读 HTTP 写入边界，以及 personal-vault 写根隔离（本地写回与 `workspace-write` 都限制在 `personal_vault/` 下）；
- 生成的公开启动数据；
- 不发现、不执行或不共享其他私人系统运行态的边界；
- 验证脚本和安全导出检查；
- 可能诱导不安全密钥或数据处理的文档。

## 哪些问题属于安全相关

以下情况应视为安全相关：

- 文档或脚本诱导提交模型密钥；
- 验证脚本漏掉明显密钥或个人机器路径；
- 示例配置意外启用真实模型调用；
- 生成文件包含敏感本地状态；
- route、extension 或生成文件暴露或调用其他私人系统；
- 仪表盘或服务器行为暴露预期项目范围之外的文件；
- 文档要求用户公开原始语料、凭据或敏感个人材料。

## 如何报告

不要在公开问题中发布利用细节、密钥、凭据或敏感示例。

推荐报告方式：

1. 如果仓库启用了安全公告或私密漏洞报告通道，请优先使用。
2. 如果没有该通道，请发送邮件到 `shiyu.hu@ntu.edu.sg`，主题写明 `ResearchOS security report`。
3. 提供最小描述、受影响文件或命令、预期影响和已脱敏的复现路径。
4. 在维护者要求提供清洗版本前，请把敏感样例留在本地。

## 安全披露预期

维护者会尽量确认有效报告，判断问题是否影响本仓库 边界，并准备修复或文档更新。在敏感细节移除或问题不再可利用前，不建议进行公开讨论。
