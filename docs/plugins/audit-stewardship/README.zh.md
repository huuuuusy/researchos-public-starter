# Audit Stewardship

## 用途

对一个有界的 claim、转换或仓库边界做只读审计，输出证据、最强反例和一个可逆修复候选。

## 使用与非目标

需要确切的基线和范围。它不做不可逆清理，也不批准自己的 finding。

## 可用性与一致性

公开版只处理公开安全来源或明确选定的本地来源。

## 依赖

需要声明式核心；reflection 与系统进化是可选交接。

## 生命周期

随版本提供并默认开启；直接只读检查仍是后备方式。

## 数据、权限与导出

无网络、命令、状态或 canonical-write 权限；所有修复都保持为 Review 候选。

## 验证

运行 `python3 scripts/validate_plugins.py` 和公开能力对齐测试。

## 故障恢复

权限或边界不清时停止，保留基线，返回最小可复现的 finding。

## 价值与替代

只有有界审计能发现普通审阅之外的重要错误时才保留。

## 退役

当该不变量被一个更小的稳定 owner 吸收时退役。

## 过程与实现

本功能的数学伪代码、控制流程与实现边界见下文。审计路由和验证脚本实现有界合同及技术检查。科学证据评价由审计者提供；三分法不会自动作出该判断。

### 有界审计

审计问题、检查集 $D(j)$ 与绑定回执 $\rho$；输出：有依据的满足、未满足和未知检查。

```pseudocode
固定审计问题、来源范围、目标版本与成功准则
对每个 $\chi\in D(j)$：
    检查同一绑定尝试的支持证据与反证
    依据证据赋予 $s_{\chi,t}(\rho)\in\{1,0,?\}$
// 缺失、过期或含糊证据保持未知，除非失败已被确立
将 $D(j)$ 分为 $D_t^1(j),D_t^0(j),D_t^?(j)$，保留根据与下一步核查
若修复已获准：
    派发另行绑定的应用
    重新审计其回执，再判断能否关闭发现
```

**算法解释。** 审计需要区分“已经不满足”与“尚不知道”。三值划分保留这一区别及其依据；修复形成新的绑定尝试，只有新回执通过核查，才有理由关闭原发现。
