# Documentation

The documents are listed in the order a newcomer needs them. Read the one that answers your question rather than all of them.

## Start here

- [README](../README.md): what ResearchOS is and what you can do in ten minutes. Read it first.
- [First-run guide](../08_exports/public_starter/onboarding-step-by-step.md): the step-by-step path from the demo to your own vault, with what you should see at each step. Follow it the first time you run anything.

## Use it

- [User Manual](user-manual.en.md): read the section you need when the guide sends you there or you want more detail. Section 1 explains the words used in the output, Section 2 one loop in your agent client, Section 3 the session scheduler, Section 4 the optional Dashboard, Section 5 your own material and Section 6 safety.

## Understand or change it

- [System Reference](system-reference.en.md): read it before you change the system. It defines states, governance boundaries, the kernel and extension architecture, the code map and the directories.
- [AGENTS.md](../AGENTS.md): what a file-aware assistant reads first in this repository; read it to see what your assistant has been told.

## Publish, extend and contribute

- [Governance and Extension Guide](governance-guide.en.md): read it before you publish anything, customize or extend the system, install a plugin or contribute; it also covers the license.
- [`reference/`](reference/): policies the guides link to when you need them: the [Agent Protocol](reference/AGENT_PROTOCOL.md), the [Context Budget Protocol](reference/CONTEXT_BUDGET_PROTOCOL.md), [Where to Put New Materials](reference/WHERE_TO_PUT_NEW_MATERIALS.md), the [Safe Export Policy](reference/SAFE_EXPORT_POLICY.md), the [Public Release Checklist](reference/PUBLIC_RELEASE_CHECKLIST.md), [Card Maturity and Enhancement](reference/CARD_MATURITY_AND_ENHANCEMENT.md), [Related Research Tools](reference/RELATED_RESEARCH_TOOLS.md) and the [commercial-use terms](reference/COMMERCIAL_USE.md).
- Repository root: the [license](../LICENSE.md) and the [contributing](../CONTRIBUTING.md), [security](../SECURITY.md) and [support](../SUPPORT.md) policies, for when you want to reuse, contribute or report a problem.

## Background

- [Technical report](technical-report.en.md) ([English PDF](technical-report.en.pdf) · [Chinese PDF](technical-report.zh.pdf)): read it when you want to know why the architecture looks this way and what evidence supports it. It has Sections 1–6 and Appendices A–B, and [Supplementary Notes 1–6](technical-report-supplement.en.md) are kept outside the PDFs. The report describes the prototype and has not been peer reviewed; current contracts, the guides and the release gates govern actual behavior.
- [V1.0.1 release notes](releases/v1.0.1.md): what changed since V1.0.
- [V1.0 release notes](releases/v1.0.0.md): what V1.0 includes and what remains limited.
