# Support

This project is meant to be understandable from the repository itself. Start with the documentation route below, then open an issue when something is unclear, broken, or under-specified.

## Find the right guide

Use the [documentation map](docs/README.md) for setup, usage, runtime and release questions. For contribution requirements, read [Contributing](CONTRIBUTING.md); report security-sensitive issues through [Security](SECURITY.md), not a public support issue.

## What to Include in a Support Request

For startup or dashboard issues, include:

- operating system;
- Python version;
- command you ran;
- port number if relevant;
- whether you used dashboard, CLI, GUI, public-starter or personal-vault mode;
- whether case materials are enabled;
- the shortest redacted error output that explains the failure.

For documentation questions, include the file and section you were reading, what you expected to learn, and where the explanation became ambiguous.

For provider or Codex questions, include the provider name, whether you are using public-starter or personal-vault mode, whether local execution was available, and the command you used to check the provider. Do not include tokens or credentials.

Never attach credentials, private research memory, personal data, or unpublished materials to any request.

## Support Boundaries

The project can support:

- setup questions about the public starter;
- bugs in demo-only scripts, validators, generated data, or dashboard behavior;
- documentation gaps;
- safe contribution questions;
- non-commercial workflow adaptation questions.

The project cannot provide:

- review of sensitive personal research data;
- management of production secrets or paid deployments;
- legal advice about commercial licensing;
- emergency security handling through public issues;
- guarantees that third-party providers behave safely in a local user environment.
