# ResearchOS 标准 Agent 提示词

这是 ResearchOS Public Starter 的标准提示词模板。它们不是临时实验 prompt，而是一套可复用的工作协议。

当你用 Codex 命令行、Codex 图形界面、其他本地助手或 API 模型提供方运行本仓库时，都可以使用这些模板。无论使用哪个提供方，都遵守同一条治理规则：材料可以在你的本地工作区中是私有的，但对外输出必须有明确的公开边界。

## 提示词 0：让 LLM 带你上手

刚下载仓库，希望 Codex、Claude Code、Gemini CLI 或其他 LLM 助手带你理解项目时使用。

### 最短默认提示词

希望节省 token 时先使用这一段。

```text
只读 AGENTS.md。不要扫描整个仓库。

请告诉我：
1. 我的路线；
2. 隐私/导出边界；
3. 下一个文件或命令；
4. 你为了节省 token 刻意没有读什么。
```

```text
我刚下载 ResearchOS Public Starter。请先只读 AGENTS.md，再判断是否需要读 docs/user-manual.zh.md 第 2 节，然后带我完成最小安全第一步。

暂时不要写文件。请先告诉我：
1. 我应该走哪条路线：学习 demo、启动仪表盘、替换示例材料、创建卡片、处理 Inbox，还是检查发布状态。
2. 你需要读取哪 0-3 个文件，以及为什么。
3. 当前涉及什么隐私、证据或导出边界。
4. 下一条命令或下一个问题是什么，如有。
5. 为了节省 token，你刻意没有读什么。
```

## 核心操作协议

任何 ResearchOS 任务都可以先加上这一段。

```text
请把 ResearchOS 当作一个小型文件化科研工具；长期研究 authority 始终属于研究者。

请按这个顺序处理：
0. 先判断这个任务是否真的需要仓库上下文。
1. 先给简洁判断：这个任务在问什么，为什么重要。
2. 再说明证据边界：哪些来自源材料，哪些是候选解释，哪些需要用户确认。
3. 再提出下一步行动：应该读什么、创建什么、验证什么、哪些保持待确认。
4. 如果任务涉及长期记忆、人物关系、公开导出、在投论文、未公开工作、敏感材料或私人笔记，只输出候选结论或候选 diff。没有用户明确确认前，不要把它写成已确认记忆或公开表述。

不要推断私人关系、指导关系、学生身份、实验室成员关系、未来承诺或贡献等级，除非用户提供明确证据。

每个输出都要标注下面一种状态：
- candidate
- needs_evidence
- confirmed_by_user
- local_only
- public_safe
- not_exportable
```

## 提示词 1：首次个人资料接入

用户填写接入笔记后使用。

```text
请读取我的接入笔记，并生成一张一级个人卡片。

只能使用我列出的来源。如果某个来源是私有、在投、未公开或仅限本地使用，你可以把它用于我的本地卡片，但由此产生的每个判断都必须标成 local_only 或 not_exportable，除非我明确说它可以公开。

请输出：
1. 个人卡片标题。
2. 公开身份锚点。
3. 本地/私人身份锚点，如有，必须标明 local_only。
4. 候选研究主题。
5. 每个主题使用的证据。
6. 缺失证据。
7. 导出边界。
8. 最小下一步升级动作。

不要推断私人关系或未来承诺。
```

## 提示词 2：第一篇论文卡片

用户上传或提供第一篇论文链接时使用。

```text
请根据这份论文材料生成一张一级论文卡片。

这篇论文可能是公开、私有、在投、审稿中、未公开或仅限本地使用。请先判断它的边界：
- public_safe
- preprint_public
- submitted_local_only
- unpublished_local_only
- confidential_not_exportable
- unknown_boundary

如果论文是在投、未公开、私有或边界不明，所有分析都保持 local_only，不要生成 public-facing 表述。

请输出：
1. 标题、年份、作者、会议/期刊/状态，如已知。
2. 来源和边界分类。
3. 简短摘要。
4. 材料支持的贡献判断。
5. 它和个人卡片的连接。
6. 从作者列表抽取的合作者候选卡片。
7. 哪些内容不能推断。
8. 下一步需要补充的证据。

共同署名只能证明共同署名，不能证明指导关系、朋友关系、实验室关系、资历顺序或未来合作。
```

## 提示词 3：合作者候选抽取

已有论文卡片后使用。

```text
请从这篇论文的作者列表中抽取合作者候选卡片。

除非我提供额外证据，否则只能使用共同署名证据和公开元数据。所有人物在我确认关系前都保持候选状态。

每个人输出一张候选卡片：
1. 姓名。
2. 来源论文。
3. 证据类型：共同作者候选。
4. 已知内容。
5. 未知内容。
6. 敏感性/导出边界。
7. 需要用户确认的问题。

不要推断指导关系、学生身份、私人亲近程度、机构关系或未来合作。
```

## 提示词 4：第二篇论文对比

用户上传第二篇论文时使用。

```text
请为第二篇论文生成卡片，并和第一张论文卡片对比。

先判断第二篇论文的边界。如果它是在投、未公开、私有或边界不明，分析保持 local_only。

请比较：
1. 共享研究主题。
2. 重复出现的作者或合作者候选。
3. 共享方法、数据集、问题或评估思路。
4. 可能的项目族关系。
5. 每条关系的证据。
6. 哪些仍只是候选解释。
7. 最小下一步行动。

除非证据或用户确认支持，否则不要把关系升级为已确认。
```

## 提示词 5：报告卡片

用于公开报告、幻灯片、讲座摘要或私人报告笔记。

```text
请根据这份报告材料生成一张报告卡片。

先判断报告边界：
- public_safe
- internal_local_only
- confidential_not_exportable
- unknown_boundary

请输出：
1. 标题、日期、场合/听众，如已知。
2. 边界分类。
3. 核心信息。
4. 关联的个人、论文、项目或主题卡片。
5. 可复用表述，并和论文证据分开。
6. 证据边界。
7. 下一步用途。

如果报告是内部或私人材料，不要生成 public-facing 表述。
```

## 提示词 6：项目或关系卡片

至少已有三张卡片后使用。

```text
请使用当前个人卡片、论文卡片、报告卡片和合作者候选卡片，生成一张很窄的项目或关系卡片。

请把已确认事实和候选解释分开。

请输出：
1. 卡片标题。
2. 使用了哪些卡片。
3. 有证据支持的连接。
4. 候选连接。
5. 每个来源的边界。
6. 用普通语言说明这条关系是什么意思。
7. 哪些内容不能得出结论。
8. 一个下一步行动。
9. 验证检查。

如果任何来源是 local_only 或 not_exportable，那么生成的关系卡片默认也是 local_only，除非我明确批准公开安全版本。
```

## 提示词 7：卡片成熟度复查

把卡片写入稳定状态前使用。

```text
请按照 ResearchOS 成熟度规则复查这些卡片。

逐张判断：
- Level 1：种子卡片，有用但不完整。
- Level 2：有来源卡片，主要判断有证据。
- Level 3：可操作卡片，有关系、下一步行动、验证检查和导出边界。

请输出：
1. 当前等级。
2. 支持该等级的证据。
3. 缺失证据。
4. 最小升级动作。
5. 它是否可以 public_safe、local_only 或 not_exportable。

不要因为卡片写得流畅就升级。只有证据和边界足够时才能升级。
```

## 提示词 8：第一张计划卡片

把卡片转成一个可执行小闭环时使用。

```text
请根据当前个人、论文、合作者、报告和关系卡片，生成一张范围很窄的计划卡片。

请输出：
1. 目标。
2. 使用了哪些卡片。
3. 使用了哪些证据。
4. 候选解释。
5. 下一步行动。
6. 负责人。
7. 时间窗口。
8. 阻塞点。
9. 验证检查。
10. 导出边界。
11. 成熟度等级。

计划必须小到可以执行。如果任何输入是在投、未公开、私有或 not_exportable，计划默认保持 local_only。
```

## 提示词 9：收件箱 / 交接处理

仪表盘或用户产生一批待处理候选项时使用。

```text
请处理 ResearchOS 收件箱或交接队列。

先逐条概览所有待处理项：
- 类型
- 标题
- 目标文件或目标卡片
- 用户指令
- 证据状态
- 敏感性/导出边界
- 当前是否能安全执行

处理规则：
1. 只处理 pending 项；不要恢复 archived、withdrawn 或 completed 项，除非用户明确要求。
2. 对确认项：accept 可以写入候选目标；reject 必须按用户修正处理；uncertain 保持 needs_evidence。
3. 对新材料：先登记；除非有可读路径，否则不要把附件文件名当作证据。
4. 对论文字段：写入前核对阶段、公开边界和证据。
5. 对人物：写任何关系卡片前，先检查敏感性和边界。
6. 对组合：解散或重构前，先保留可复用经验。
7. 在投、未公开、敏感和私人材料默认 local_only。
8. public-facing 输出需要明确 public_safe 批准。
9. 写入后重建生成数据并运行验证。

请输出：
- 收件箱概览
- 执行计划
- 每条处理结果
- 修改文件清单
- 验证结果
- 需要用户确认的问题
```

## 提示词 10：外部请求路由

用于回复邀请、合作请求、报告请求、审稿请求、proposal 机会或类似外部需求之前。

```text
我收到这个外部请求：[粘贴请求]。

请用 ResearchOS 帮我判断应该怎么回应。请读 AGENTS.md、docs/reference/AGENT_PROTOCOL.zh.md 和 05_workflows/research_management/external-demand-response-workflow.zh.md。

请输出：
1. 请求类型。
2. 请求中的来源事实。
3. 相关 ResearchOS 资产。
4. 适配判断。
5. 缺失信息和风险。
6. 隐私/导出边界。
7. 推荐回应 stance。
8. 只有安全时才给回复草稿。
9. 可以记录的候选记忆。

不要在没有明确证据时推断可用时间、私人亲近程度、指导关系、贡献层级或未来承诺。
```

## 提示词 11：关系机会路由

用于判断某个人、论文、活动、机构、主题或项目是否可能形成研究机会。

```text
我想知道这个信号是否形成研究机会：[人物/论文/活动/项目/主题]。

请先读 AGENTS.md 和 05_workflows/research_management/relationship-opportunity-workflow.zh.md。只有需要创建或更新卡片时，再补读 docs/reference/AGENT_PROTOCOL.zh.md 和一个匹配模板。

请输出：
1. 已确认公开事实。
2. 候选连接。
3. 相关资产。
4. 机会路线。
5. 不能推断什么。
6. 敏感性/导出边界。
7. 推荐下一步行动。
8. 候选卡片或更新目标。

不要推断指导关系、学生身份、实验室成员关系、私人亲近程度、贡献层级、未来合作或对方愿意被联系。
```

## 私人和在投材料的边界规则

ResearchOS 可以帮助你在自己的本地/私人工作区处理私有、在投、审稿中或未公开材料。这和把材料提交到公开仓库、或生成公开表述不是一回事。

默认规则如下：

| 材料状态 | 本地分析 | 公开导出 |
| --- | --- | --- |
| 公开论文/网页 | 可以 | 证据检查后可以 |
| 公开预印本 | 可以 | 必须标明版本/状态 |
| 在投或审稿中 | 本地可以 | 默认不可以，除非明确放行 |
| 未公开草稿 | 本地可以 | 默认不可以 |
| 保密审稿/学生/人物材料 | 仅在合适的本地边界内可以 | 不可以 |
| 边界不明 | 按 local_only 处理 | 不可以 |

不确定时，把卡片标成 `local_only`，并请用户确认导出边界。

## Agent Summary

ResearchOS 公开安全标准提示词模板，覆盖个人资料接入、论文卡片、合作者抽取、第二篇论文对比、报告卡片、关系卡片、成熟度复查、计划卡片、收件箱/交接处理、外部请求路由和关系机会路由。
